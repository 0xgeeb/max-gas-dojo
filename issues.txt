CODE REVIEW FINDINGS - Martial Hero Fighter
===========================================

🔴 CRITICAL ISSUES (Must Fix Immediately)
==========================================

1. Smart Contract Security Flaw - Unlimited Token Minting
   Location: /contracts/src/WC.sol:17-23
   Severity: CRITICAL
   Description: WC token contract has no access control on mint and burn functions.
   Anyone can mint unlimited tokens or burn anyone's tokens! This completely breaks
   the token economy.

   Current Code:
   ```
   function mint(address _to, uint256 _amount) external {
       _mint(_to, _amount);  // No access control!
   }
   ```

   Fix: Add access control (e.g., Ownable) or remove these functions entirely.

2. WalletButton Race Condition
   Location: /client/src/components/walletButton/index.tsx:10-24
   Severity: CRITICAL
   Description: The wallet connection is asynchronous, but the code checks
   `if (address)` immediately after calling `connectWallet()`. The address won't
   be set yet, so `joinLobby` will never execute.

   Current Code:
   ```
   await connectWallet();
   if (address) {  // address is still the OLD value here!
       gameEngine.joinLobby(address);
   }
   ```

   Fix: Use a useEffect to watch for address changes, or pass the returned address.

3. Memory Leaks from Uncanceled Timeouts [FIXED]
   Location: /server/server.js:303, 307, 645-666
   Severity: CRITICAL
   Description: Multiple setTimeout calls create timeouts that aren't tracked or
   cleared if players disconnect early. This causes memory leaks.

   Current Code:
   ```
   setTimeout(() => {
       if (defender.state === 'takeHit') {
           defender.state = 'idle';
       }
   }, 300);  // Never stored, can't be cancelled!
   ```

   Fix: Store timeout IDs and clear them on cleanup.

4. CORS Wildcard in Production [FIXED]
   Location: /server/server.js:13
   Severity: CRITICAL
   Description: Using `origin: "*"` allows any website to connect to your server,
   enabling potential attacks.

   Current Code:
   ```
   cors: {
       origin: "*",  // DANGEROUS in production!
   ```

   Fix: Set specific allowed origins for production.


🟡 HIGH PRIORITY ISSUES
========================

5. No Blockchain Validation for Match IDs [FIXED]
   Location: /server/server.js:619, 671-698
   Severity: HIGH
   Description: The server accepts `matchId` from clients without verifying it
   exists on the blockchain. Malicious clients could send fake IDs.

   Fix: Call `resolver.getMatch(matchId)` to validate before accepting challenges.

6. Challenge Expiration Race Condition [FIXED]
   Location: /server/server.js:645-666
   Severity: HIGH
   Description: If a challenge is deleted (e.g., player disconnects) before the
   expiration timeout fires, the timeout will try to access non-existent data and
   cause errors.

   Fix: Check if challenge exists before accessing it in the timeout callback.

7. Missing Reconnection Logic
   Location: /server/server.js:891-951
   Severity: HIGH
   Description: If a player disconnects during a fight, there's a 30-second timeout
   but no way to reconnect to the ongoing match if they refresh or lose connection.

   Fix: Implement reconnection logic using session tokens or wallet addresses.

8. Player Sprite Memory Leak [FIXED]
   Location: /client/src/game/GameEngine.js:305
   Severity: HIGH
   Description: Player sprites are created but never removed from the `playerSprites`
   Map when players leave, causing memory accumulation.

   Fix: Clean up sprites when players disconnect.

9. Hardcoded Event Signature [FIXED]
   Location: /client/src/providers/WalletProvider/index.tsx:102
   Severity: HIGH
   Description: The MatchCreated event signature is hardcoded. If you redeploy the
   contract, this will silently break.

   Current Code:
   ```
   log.topics[0] === '0x2c9089bdab8aeea6a8c5e41b785290b63781dd5c648c9c824bcc0883237cff32'
   ```

   Fix: Use viem's `parseEventLogs` or `decodeEventLog` with the ABI.

10. Challenge Map Memory Leak [FIXED]
    Location: /server/server.js:397, 645-666
    Severity: HIGH
    Description: Expired/declined challenges are never removed from the `challenges`
    Map, causing memory growth over time.

    Fix: Delete challenges after they expire or are resolved.
